# 演示输入素材包 —— 上台照着这个粘就行

**这个包只解决一件事：演示当场要输入的每一样东西，都提前准备好，现场不现编。**
方案样本、每一问该答什么、面试那半发什么，全在里面。

演示的输入只有三个地方：**粘贴方案** → **回答评审的提问** → （可选）**面试那半发一句话**。
其他的点击都不用输入字。

---

## 一、包里有什么

| 文件 | 干什么用的 |
|---|---|
| `00_演示输入包.md` | 就是这份说明：现场照着走流程 |
| `10_回答稿.txt` | **最重要**。四位评审各准备了三段答话（答虚 / 半答 / 认真），现场看着屏幕挑一段粘 |
| `20_模拟面试输入.txt` | 演示第 10 步（模拟面试那半）要发的句子和答案，含"故意答不知道"的版本 |
| `90_预跑记录.md` | 实测存档：它真的会问什么、三种答法被判成什么样、耗时多少 |
| `方案样本/demo_plan.txt` / `demo_plan.docx` / `demo_plan.pdf` | **演示主线方案**（校园二手教材平台，705 字）。三种格式都有，现场想演"上传文件"就点 docx 或 pdf |
| `方案样本/sample_plan_eldercare.txt` / `sample_plan_eldercare.docx` / `sample_plan_eldercare.pdf` | **备用方案**（社区居家养老陪护，891 字）。主线方案抽要素不理想时换它上 |
| `方案样本/sample_plan_en.pdf` | 最后的备用：同一类项目的英文版，中文方案实在不顺时用它 |

方案文件放在 `方案样本/` 里，复制粘贴时别拷错 `demo_plan` 和 `sample_plan_eldercare` ——
两份都是"项目名称：……"开头，看第一行的项目名区分。

## 二、上台前 10 分钟的准备

1. 起服务：`python -m app.main`，打开 http://localhost:8000
2. **登录好并停在主界面**（登录要真发邮件验证码，现场不要赌邮件）
3. 打开这个文件夹，双击 `10_回答稿.txt`（用记事本打开就行）
4. 把 `方案样本/demo_plan.txt` 的内容**先复制到剪贴板**（Ctrl+A、Ctrl+C）
5. 先把服务跑一遍热一下（Redis / PostgreSQL / 模型连接首次调用会慢）：随便提交一次方案即可
6. 浏览器缩放 100%、全屏、关掉无关标签页

> 上台前一定先跑一次预跑：
> `D:\anaconda3\envs\agent_env\python.exe scripts\dry_run_demo.py --strategy demo --expect-cross --expect-followup`
> 它非零退出就说明这一场没同时出现"接话"和"追问"，换一次重跑 —— 别赌。

## 三、现场流程（对着做）

| # | 我做什么 | 手上粘什么 | 屏幕上应该看到 |
|---|---|---|---|
| 1 | 左侧点「交叉质询评审团」 | 不用输入 | 出现提交方案的输入区 |
| 2 | 粘贴方案，点提交 | 剪贴板里的 `demo_plan.txt` | 要素表（项目目标/技术方案/预算与资源：未提及/……/方案缺失项） |
| 3 | 等，不说话 | — | 四位评审依次发言：技术 → 成本与进度 → 合规与伦理 → 用户与价值 |
| 4 | **停一下，指屏幕** | — | 气泡上带 `⟶ 接 XXX 的话`，这就是交叉质询 |
| 5 | 第 1 问答得虚 | `10_回答稿.txt` 里的 **[T1]** | 判定：未解决（严重度 3）+ 理由 |
| 6 | 等追问 | — | 同一个评审带 `↳ 追问` 再问一层 |
| 7 | 追问认真答 | **[C3]**（带数字那段） | 判定：**已答清楚**，而且不进最后那份清单 |
| 8 | 剩下的每一问 | 点「跳过」即可 | 每跳过一条，判定"学生没有回答这个问题" |
| 9 | 散会后滚到下方 | — | 会议纪要时间线 + **未答好的问题清单（按严重度降序）** |
| 10 | 回「模拟面试」 | `20_模拟面试输入.txt` 第一句 | 出一道题、评分、点评 |

**看不懂第 5~7 步在干嘛？** 那是故意的：答虚 → 被追问 → 认真答 → 判定翻盘。
三行判定就是"这系统真在判断我答没答到点上"的证据（原文见 `90_预跑记录.md` 第二节）。

## 四、每一问该粘哪段（按"谁在问"找，不按题号找）

模型的提问措辞每次都不一样，所以按提问的**评审**和**关注点**找：

| 屏幕上是谁在问 / 问的是什么 | 粘 `10_回答稿.txt` 里的 |
|---|---|
| 技术评审：有没有必要用大模型、会不会过度设计、有没有更简单的做法 | 演示用 **[T1]**（答虚）或 **[T3]**（认真） |
| 成本与进度评审：调用量多少、多少钱、谁出钱、人手够不够、10 周够吗 | 演示用 **[C2]**（半答）；被追问"到底多少钱"用 **[C3]** |
| 成本与进度评审：封面识图多少次、多少钱 | **[C4]** |
| 合规与伦理评审：封面照片授权、隐私、存多久、算法偏见 | **[P2]** 或 **[P3]** |
| 用户与价值评审：5000 人数据哪来的、做过问卷吗、比 QQ 群/闲鱼强在哪 | **[U2]** 或 **[U3]** |
| 不想答了 / 时间不够了 | 直接点「跳过」（等于 **[S1]**） |

**现场的推荐打法**：第 1 问用 [T1] 逼出追问，追问用 [C3] 演一次"已答清楚"，
剩下的一路跳过 —— 三种判定都看到了，时间也压得住（跳过的判定是 0 秒级的）。

## 五、三个"如果"

| 情况 | 怎么办 |
|---|---|
| 接话一直没出现 | 别硬等。说"接话是评审自己判断触没触碰关注点，属概率事件；本地小模型更保守"。→ 重新提交一次方案再开一场（预跑确认过商业模型下 4/4 场都出现了） |
| 追问没来 | 不硬等。用 `10_回答稿.txt` 的 **[S3]** 把机制讲清楚：追问要"判定模型认为没被说服、并给出追问方向"才触发，每个议题最多追 1 层，就是为了不让答辩拖太久 |
| 页面刷新了 / 服务要重启 | 直接说"学生回答是另一次请求，会议状态在 PostgreSQL 检查点里" → 刷新后带同一个会话继续答，这就是最好的现场证明 |

## 六、最终交付物（第 9 步那份清单要指着说）

散会后屏幕下方那份**未答好的问题清单**，是整场唯一的产出物：
每条都带严重度，按严重度降序排。实测这场 9 问里出了 7 条
（"已答清楚"的那条不在里面 —— 这一点一定要指着说，否则评委以为它只会挑刺）。

一句话讲法：**"这不是打分，是一张改稿工单 —— 它告诉我方案里哪一句话经不起追问。"**

## 附：这个包怎么来的 / 怎么再生成

- `docs/演示输入素材包/` 下的样本由 `scripts/make_demo_inputs.py` 从 `data/` 收进来并补齐三种格式；
  跑 `python scripts/make_demo_inputs.py` 会重新准备并自检（缺文件、字数对不上、回答稿缺维度都会报错）。
- 回答稿里的数字（10 万次调用、0.1 元、1200 份问卷、62%）是**示例**，
  上台前换成你们自己的真实数字 —— 换完不用改代码，改 `10_回答稿.txt` 就行。
